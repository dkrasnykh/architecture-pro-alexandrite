### **Существующие проблемные места:**<br>
1. Запросы, на расчет стоимости заказов, прерываются по таймауту.
2. Дашборд с заказами долго загружается у операторов. Запросы на чтение и на запись обрабатывает один инстанс базы данных MES. Из-за этого (в том числе) дашборд с заказами долго загружается у операторов. (репликация).
3. Клиенты, которые оформляют заказы без участия селлеров не видят актуальный статус заказа (запросы прерываются по таймауту, клиенты считают, что их запрос до сих пор в работе).

### **Потенциальные проблемные места:**<br>
1. Длинный релизный цикл 
2. Нехватка ресурса разработки

### **Инициативы, необходимые для устранения нежелательных ситуаций:**<br>
1. Развернуть несколько инстансов приложения MES. 
2. Настроить репликацию базы данных MES (мастер и две реплики).
3. Нанять qa инженеров (автотестирование).
4. Настроить на dev окружении авто прогон e2e тестов после мержа. Так разработчик сможет отследить падения тестов на своих изменениях без деплоя в release окружении.
5. Для клиентов (b2b и b2c) должна быть одна точка входа для оформления заказов. В интерфейсе пользователя должна отображаться рассчитанная стоимость и актуальный статус. Все заказы должны проходить через CRM систему, за каждым заказом должен быть закреплен менеджер (селлер, продавец). В систему MES все заказы должны попадать через очередь. Обновления по заказу (рассчитанная стоимость, обновления статуса) должны попадать из MES в CRM через очередь. Все изменения здесь - [Архитектура через пол года](to_be.png).
6. Настроить кеширование для MES приложения операторов.
7. Настроить репликацию базы данных CRM.
