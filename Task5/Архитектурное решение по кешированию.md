### **Анализ:**<br>

Полный список проблем описан в Task1. Основные проблемы связаны с зависанием заказа на этапе расчета цены (тут запросы отваливаются по тайм-ауту скорее всего). Эта проблема будет решена развертыванием дополнительных инстансов сервиса расчета стоимости изделия. 

И проблема с отображением статусов в интерфейсе операторов. Когда применим изменения из Task1 (будут отдельные реплики на чтение), ситуация изменится в лучшую сторону. Но статусы заказов можно кешировать. Чтобы каждый запрос на чтение не обращался к базе данных, а брал данные из кеша (если они не менялись).

### **Мотивация:**<br>
Кеширование необходимо внедрить для api операторов для работы с заказами. Это решит проблему обновления данных о заказах в интерфейсе. Операторы оперативнее начнут брать в работу новые заказы. Сократится время ожидания клиента. 

### **Предлагаемое решение:**<br>
В каждом пользовательском сценарии (описаны в Task3) оператор выполняет одни и те же действия:

(MES) Отбирает заказы в статусе (MANUFACTURING_APPROVED);<br>
(MES) Оператор взял заказ в работу (MANUFACTURING_STARTED);<br>
(MES) Оператор выполнил заказ (MANUFACTURING_COMPLETED);<br>
(MES) Оператор начал упаковывать заказ (PACKAGING);<br>
(MES) Заказ отправлен покупателю (SHIPPED).<br>

Будем внедрять серверное кеширование, паттерн Write-Behind:
Кеширование снимет нагрузку на чтение к базе mes_db. Нагрузка на запись будет асинхронной: данные будет попадать в кеш, будет сформована задача в очередь на запись в базу данных. Пользователю вернётся ок, апдейт записи в базы выполнится асинхронно. 
Очередь задач на обновление базы данных позволит управлять нагрузкой на запись в бд.

Способы инвалидации кеша: 
Инвалидация по ключу - подход Write-Behind включает такой механизм (ключ: номер заказа, значение: данные заказа). Оператор на своей стороне в заказе меняет только статус. Если через кеш проходит запрос на изменение статуса, то статус меняется в кеше и формируется задача на обновление статуса в бд. 

При рестарте приложения, следует прогревать кеш, заказы в статусах CLOSED не нужно показывать оператору.
